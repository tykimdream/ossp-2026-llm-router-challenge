# Robust V2 적대적 리뷰와 V3

## 결론

> 이 문서는 v3 결정 당시의 기록이다. 이후 공정 Train-only → Dev에서 v1을
> 이긴 Risk Router v4가 활성화되었다. 현재 상태는
> [`SUBMISSION_ROUTER.md`](SUBMISSION_ROUTER.md)를 기준으로 한다.

V3는 V2의 검증 누수, 근거가 약한 비용 stress, 대형 입력의 사전 정렬을
고쳤다. 대신 공개 Dev 점수는 더 낮다. 따라서 **V3는 강건성 실험으로 보존하고
현재 제출 진입점은 V1 그대로 유지**한다. 이 판단은 점수와 안전성 중 하나를
숨기지 않고 둘을 분리해 비교한 결과다.

## V2를 공격해 발견한 문제

| 공격 관점 | V2에서 발견한 문제 | 위험 | V3의 처리 |
| --- | --- | --- | --- |
| 검증 누수 | 등급별 Uplift/Hybrid 조합과 `1.02/1.05` 배수 선택에 Dev 결과가 관여 | Dev 점수가 숨은 평가에서 재현되지 않을 수 있음 | Train의 템플릿 그룹 5-fold OOF만으로 predictor와 안전계수 선택 |
| Premium 분포 이동 | V2 Hybrid Premium의 Train OOF 실제 비용은 전체 `4.013`, 최악 fold `5.010` | 공식 한도 `4.0`과 내부 목표 `3.5`를 모두 넘을 수 있음 | 최악 fold까지 `3.5` 아래인 Uplift 선택; 관측 최악값 `3.476` |
| 가상 시나리오 | 여러 시나리오가 문항별 최대 비용 하나로 합쳐짐 | 이름은 다중 시나리오지만 실제로는 고정 비용 팽창 하나와 같음 | 가상 배수 삭제, 실제 OOF fold 비용으로 안전계수 보정 |
| stress 크기 | AX31 `1.02`, K1 `1.05`는 공개 자료의 긴 비용 꼬리에 비해 근거가 약함 | 작은 배수로 실제 극단 비용을 방어한다고 오해할 수 있음 | 내부 목표 `1.18/1.85/3.5`와 최악 fold 통과 여부를 직접 사용 |
| 대형 입력 | 경량 fallback 여부를 보기 전에 전체 입력을 정렬 | 공격적으로 큰 입력에서 시간·메모리를 먼저 사용 | 문항 수·문자 수를 정렬 전에 검사하고 즉시 점별 휴리스틱 실행 |
| 반복 횟수 | 80회 이분 탐색은 근거 없이 매우 보수적 | 결과 이득 없이 반복 비용 증가, 발표 근거 부족 | 고정 48회; 공개 2,640문항 세 등급에서 80회와 불일치 `0` |
| 계산 중복 | V2는 모든 component artifact를 받고 Premium에서 별도 Hybrid 경로 실행 | Premium 런타임 증가 | V3는 Uplift artifact 하나만 예측 |

공개 Train의 문항별 실제 비용 비율은 K1/Light 기준 중앙값 약 `23.5`,
95백분위 약 `230.6`, 99백분위 약 `558.0`, 최댓값 약 `10,353`이었다.
따라서 `1.05` 같은 고정 배수는 비용 예측 오차 전체에 대한 보장이 아니다.

## V1·V2·V3 벤치마크

### Train-only 모델로 Dev 평가

`공정`은 Dev outcome을 모델·조합·안전계수 선택에 쓰지 않았다는 뜻이다.
V2는 component 모델만 Train에서 만들었지만 조합을 Dev를 본 뒤 골랐으므로
공정 점수로 주장할 수 없다.

| 버전 | 검증 상태 | 최종 점수 | Fast 비용 | Balanced 비용 | Premium 비용 |
| --- | --- | ---: | ---: | ---: | ---: |
| V1 Ridge | 공정 | **0.687187** | 1.190838 | 1.884889 | 2.923078 |
| V2 Fixed Scenario | Dev 조정 | **0.687983** | 1.122335 | 1.588707 | 3.299693 |
| V3 Train-OOF Uplift | 공정 | 0.685966 | **1.127580** | **1.608746** | **2.694441** |

V3는 V1보다 `0.001222`, V2의 참고값보다 `0.002017` 낮다. 반대로 V1 대비
모든 등급에서 비용이 낮고, 특히 Premium 비용을 `0.229` 줄였다.

### Train+Dev 재학습 artifact를 같은 Dev에서 재측정

아래 값은 학습에 Dev가 포함된 배포 확인값이지 일반화 점수가 아니다.

### 동일 Mac, 공개 2,640문항 인프로세스 실행

프로세스·컨테이너 시작 시간을 제외하고 각 등급을 2회 실행한 중앙값이다.
모두 90초 제한보다 충분히 빠르다.

| 버전 | Fast | Balanced | Premium | 반복 출력 |
| --- | ---: | ---: | ---: | --- |
| V1 | 14.364초 | 14.346초 | 14.393초 | 동일 |
| V2 | 14.276초 | 14.265초 | 16.089초 | 동일 |
| V3 | **14.246초** | **14.218초** | **14.254초** | 동일 |

V3의 48회와 기존 80회 선택기는 공개 2,640문항의 Fast, Balanced, Premium
모두 선택 불일치가 `0`이었다. Dev 880문항 Premium에서 문항 ID를 전부 바꾸고
순서를 뒤집은 공격도 내용별 선택 불일치가 `0`이었다.

## 남은 취약점과 제출 판단

- 라우팅 시점에는 실제 출력 토큰 수를 모르므로 숨은 평가 비용의 수학적 절대
  보장은 할 수 없다. V3는 공개 Train의 최악 문제유형 fold와 내부 마진으로
  위험을 낮춘다.
- 선형 Uplift 모델은 공개 데이터에 없는 새로운 문제 유형과 극단적으로 긴
  출력 비용을 정확히 예측하지 못할 수 있다.
- V3의 안전성 향상은 현재 점수 하락을 상쇄하지 못한다. 따라서 V3를 활성
  제출로 교체하지 않고 V1, V2와 함께 재현 가능한 실험으로 보존한다.
